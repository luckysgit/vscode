Layer 1: Multi-Modal Data Ingestion Layer1. Cyber Telemetry & Network FlowsDataset Used: UNSW-NB15 Network Telemetry Benchmark.  Why This Dataset: Unlike synthetic lab captures, UNSW-NB15 mirrors modern low-and-slow reconnaissance, port scans, and command-and-control (C2) channel handshakes.  What Information It Contains: 49 structured network flow features, including source/destination IP addresses, port numbers, duration, packet counts, TTL (Time-to-Live) values, protocol flags (TCP, UDP, ICMP), and transaction round-trip states.  Operational Value: Discovers reconnaissance probes against critical infrastructure and unauthorized lateral scans.  2. Delivery & Weaponized InfrastructureDataset Used: Pirocheto Phishing & Malicious URL Corpus.  Why This Dataset: Hostile staging cells rely heavily on disguised hostnames, shortened delivery URLs, and typo-squatted domains to harvest credentials or stage malware payloads.  What Information It Contains: Raw URLs, full HTTP strings, top-level domain (TLD) classifications, and labels indicating malicious versus benign infrastructure.  Operational Value: Identifies domains being set up or accessed by actors during preliminary staging.  3. Cellular Mobility & Telecom CDR FeedsDataset Used: Synthetic Telecommunications Call Detail Record (CDR) & Cell Tower Logs.  Why This Dataset: Telecom logs expose physical operational security (OPSEC) tradecraft—specifically burner phone usage and co-location—that cyber sensors miss entirely.  What Information It Contains: Mobile Station International Subscriber Directory Numbers (MSISDNs / phone numbers), International Mobile Equipment Identity (IMEI / handset hardware IDs), Cell Tower IDs with associated latitude/longitude coordinates, call durations, and precise event timestamps.  Operational Value: Pinpoints physical burner phone activation rings, IMEI churn (multiple SIM cards swapped into a single physical phone), and geographic transit patterns.  Layer 2: Perception & Domain-Specific Model Inference1. Network Behavior ModelModel Architecture: XGBoost Classifier (max_depth=3, eval_metric="logloss", learning_rate=0.1).  Why This Model: Tabular network flows feature non-linear boundaries, heterogeneous scales, and sparse features that cause deep neural networks to overfit unless heavily regularized. Gradient-boosted decision trees naturally partition these metrics efficiently.  Input: Numerical flow vector (duration, packet count, rate, error flags).  Output: Calibrated cyber anomaly probability score $P(\text{attack}) \in [0, 1]$.  2. Domain & Delivery ClassifierModel Architecture: Character N-Gram (3–5) TF-IDF + Balanced Logistic Regression.  Why This Model: Hostile domains rarely rely on standard vocabulary; they utilize character-level variations (e.g., secure-login-v4.com, auth-portal-gov[.]org). Character n-grams directly capture lexical entropy and sub-word indicators without requiring heavy language models.  Input: Raw URL string.  Output: Malicious infrastructure confidence score $P(\text{malicious}) \in [0, 1]$.  3. Cellular Mobility & Burner DetectorModel Architecture: Isolation Forest + Sequential IMEI Churn Estimator.  Why This Model: Unsupervised tree isolation efficiently identifies anomalous outliers in mobility records (e.g., sudden bursts of late-night calls or rapid geographic relocations exceeding normal human velocity).  Input: IMEI churn counts, nighttime communication ratios, and cell tower transit velocity.  Output: Telecom anomaly risk score $P(\text{burner}) \in [0, 1]$. Layer 4: Semantic Embedding & Vector Retrieval Engine1. Embedding ModelTechnology: BAAI/bge-m3 (1024-dimensional dense semantic vectors).  Why This Technology: Multi-modal threat investigations require cross-lingual mapping across unstructured intelligence reports, hacker aliases, and text descriptions of MITRE ATT&CK techniques. bge-m3 provides dense vector retrieval, multi-lingual support, and high semantic precision for technical threat intelligence taxonomies.  What It Embeds: Unstructured threat reports, actor alias variants (e.g., "Fancy Bear", "APT28", "Strontium"), and formal MITRE ATT&CK scope descriptions.  2. Vector Store StorageTechnology: ChromaDB / In-Memory FAISS (Colab workbench) $\rightarrow$ Neo4j Vector Index (Production).  Why This Technology: Allows nearest-neighbor search ($k$-NN via cosine similarity) to instantly link an observed event indicator to a documented Advanced Persistent Threat (APT) tactic without manual rule creation.  Layer Output: Semantic similarity scores matching active telemetry to known threat actors and techniques.  Layer 5: Entity Resolution & Knowledge Graph Assembly1. Automated Entity Resolution (Resolving Disparate Indicators)Instead of relying on synthetic ID assignments, the graph resolves identities using:Infrastructure Joining: Merging distinct actors if they share an IP within the same /24 CIDR block or identical BGP Autonomous System Numbers (ASNs).  Co-Location Algorithms: Calculating spatial-temporal overlap between two devices consistently switching cell towers within 15 minutes without placing direct calls to each other.  Layer 6: Composite Risk Scoring & Temporal Actor Tracking1. Fused Cross-Domain Risk FormulaTo elevate multi-domain operations over isolated alerts, the engine applies weighted multi-source scoring with a cross-domain convergence booster:  $$\text{Composite Risk}(A) = \sum_{m \in M} w_m \cdot R_m(A) + \gamma \cdot \mathbb{I}(\vert{}\mathcal{M}_A\vert{} \ge 3)$$Calibrated Weights:Cyber NetFlow Telemetry ($w = 0.35$)  Malicious URLs / Staging Infrastructure ($w = 0.25$)  MITRE CTI Technique Attribution ($w = 0.20$)  Telecom Mobility / Burner Phone Anomalies ($w = 0.20$)  Multi-Source Booster ($\gamma = 0.35$): Applied as an operational penalty when three or more distinct domains independently flag the target.  Why This Matters: An actor with four moderate alerts ($0.65 \times 4$) receives a higher investigation priority than an entity with a single high-volume network alert ($0.95$), directly addressing weak-signal invisibility.  2. Temporal Actor TrackingCentrality Drift: Measures Betweenness Centrality over discrete time windows ($T_1, T_2, T_3$). An actor transitioning from a low-degree peripheral node to a high-betweenness connector signals operational coordination.  Timeline Extraction: Sequences indicators chronologically to identify attack lifecycles (Reconnaissance $\rightarrow$ Infrastructure Staging $\rightarrow$ Operational Activation).  Layer 7: Controlled Retrieval Layer (Read-Only MCP Server)Generative LLMs hallucinate when fed raw, unformatted logs. The platform uses a Read-Only Model Context Protocol (MCP) Tool Server that provides the language model with deterministic, structured endpoints:  get_actor_linkage_graph(actor_id: str) -> dict: Retrieves the 1-hop and 2-hop graph topology, returning all linked IPs, domains, devices, and cell towers.  get_infrastructure_timeline(actor_id: str) -> dict: Returns a time-indexed sequence of all cyber reconnaissance and domain activities tied to the actor.get_telecom_co_location(actor_id: str) -> dict: Queries cellular metadata for IMEI churn frequency, cell tower transitions, and co-traveling devices.  get_threat_actor_attribution(actor_id: str) -> dict: Queries the STIX knowledge graph to return confirmed APT group signatures and MITRE techniques.
